<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| customer slip upload → API | Untrusted image + implied payment claim. |
| API → SlipOK | Slip leaves the system boundary to a third-party verifier (PDPA disclosure). |
| API → R2 (private) | Slip stored; must never be public. |

## STRIDE Threat Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-19 | Spoofing | forged / someone-else's slip accepted | high | mitigate | Verify payee (branch-linked account, D-02) + exact amount (D-03); reject otherwise. |
| T-02-20 | Repudiation | one slip paying two orders | high | mitigate | transRef UNIQUE system-wide; unique-violation = 409 duplicate (D-06 / Pitfall 3), not vendor-only. |
| T-02-21 | Information Disclosure | slip image leaking via public URL | high | mitigate | Private bucket + server-assigned key + short-TTL signed URL only; never /files/presign, never public (D-28). |
| T-02-22 | Tampering | client overwriting another order's slip via chosen key | high | mitigate | Server-assigns slips/{orderId}/{uuid}.jpg; client never supplies the key. |
| T-02-23 | Denial of Service | SlipOK down blocking all payments | medium | mitigate | "unavailable" → awaiting_review + admin manual-confirm (D-04); store never hard-depends on the vendor. |
| T-02-24 | Information Disclosure | SLIPOK_API_KEY / raw slip in logs | high | mitigate | Env-only key; structured logs never include the key or slip bytes (Phase-0 D-15). |
</threat_model>
