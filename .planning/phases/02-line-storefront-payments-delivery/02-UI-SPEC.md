# Phase 2 — UI Design Contract

> Visual and interaction contract for the LINE LIFF storefront (browse → checkout wizard → PromptPay pay → slip upload → order history/reorder). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Surface:** LINE in-app browser (LIFF mini-app), mobile-first, Thai-language (NFR-07 / LINE-02). Rendered inside LINE's WebView on Android/iOS. All copy is Thai (matches the locked Thai Rich Menu labels in CONTEXT D-18). Rich Menu images and Flex-message cards render in the LINE client itself, not the DOM — their copy is contracted here; their pixel layout is CONTEXT Claude's-discretion (D-22).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn is React-only; this app is Vue 3.5 + Tailwind v4 (CSS-first). Components are hand-built Vue SFCs in `web/src`. |
| Preset | not applicable |
| Component library | none (headless, hand-built SFCs). Keep dependency count low per NFR-08. |
| Icon library | `lucide-vue-next` (tree-shaken, only imported glyphs ship — small footprint, consistent 1.5px stroke). Alternative if a dep must be avoided: inline SVG sprite. |
| Font | **Sarabun** (Thai + Latin) via self-hosted `@font-face` (weights 400 + 600 only). Chosen for Thai legibility on small screens and because it is already the project's Thai font for invoices (CLAUDE.md pdfmake). Self-host the two weights (do not Google-Fonts-CDN) so the LIFF first paint is fast and offline-tolerant. System-font fallback: `"Sarabun", system-ui, -apple-system, "Noto Sans Thai", sans-serif`. |

**Design tokens live in Tailwind v4 CSS-first config.** Create `web/src/style.css` with an `@theme { }` block declaring the tokens below as CSS custom properties (`--color-*`, `--spacing-*`, `--font-*`), imported once in `main.ts`. No `tailwind.config.js` — v4 is CSS-first (CLAUDE.md).

## Spacing Scale

Declared values (8-point scale, all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, chip inset, badge padding |
| sm | 8px | Compact spacing (form field internal, list row gaps) |
| md | 16px | Default: screen horizontal padding, card padding, gap between form fields |
| lg | 24px | Section padding, gap between wizard sections |
| xl | 32px | Major block breaks, above the sticky footer CTA |
| 2xl | 48px | Empty-state vertical centering, top of QR/confirmation screens |
| 3xl | 64px | Full-screen state (success/paid) vertical rhythm |

**Exceptions (mobile touch-target minimums — WCAG 2.5.5 / NFR-07):**
- Interactive controls (buttons, delivery-method selectors, stepper +/−, checkbox rows, Rich Menu content links) have a **minimum 44×44px hit area**, even when the visual glyph is smaller. Achieve via padding, not by breaking the 4px scale.
- Primary CTA button height: **48px** (comfortable thumb target at the bottom of the wizard).
- Sticky checkout footer sits above the iOS safe-area inset (`env(safe-area-inset-bottom)`; `viewport-fit=cover` is already set in `index.html`).

## Typography

Mobile-first scale. Exactly 4 sizes, exactly 2 weights. Line-heights are bumped slightly above Latin norms because Thai has stacked vowel/tone marks that need vertical room.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display (screen title, price total, "ชำระเงิน" heading) | 28px | 600 semibold | 1.3 |
| Heading (section titles, variety name, wizard step title) | 20px | 600 semibold | 1.35 |
| Body (default text, descriptions, form values, care tips) | 16px | 400 regular | 1.6 |
| Label (field labels, captions, badges, helper/error text, delivery-fee line) | 14px | 400 regular (600 when a label must emphasize, e.g. selected method) | 1.5 |

Rules:
- **Never go below 14px** — minimum readable Thai size in the LINE WebView.
- Prices shown to the customer use Body or Display size at weight 600 for the number, with the `฿` symbol at the same size (e.g. `฿120`, free-shipping threshold "ส่งฟรีเมื่อซื้อครบ ฿500").
- Only two weights ship (400, 600). No light/thin/bold-800.

## Color

Fresh-salad brand: near-white canvas, soft leaf-green secondary surfaces, one saturated leaf-green accent reserved for action and "go/paid" affordances. 60/30/10 split.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background, primary content surface, wizard body |
| Secondary (30%) | `#F1F5EC` | Cards, list rows, delivery-method tiles, sticky footer, section dividers (soft green-tinted neutral) |
| Accent (10%) | `#2E7D32` | See reserved list below (contrast 4.6:1 on white — passes WCAG AA for normal text; button text on accent is `#FFFFFF`) |
| Destructive | `#D32F2F` | Destructive/failure only (see reserved list) |

**Supporting neutrals (not part of the 60/30/10 budget — text/border ink):**
- Text primary: `#1B2A1B` (near-black green-ink) — body/headings.
- Text muted: `#5B6B5B` — labels, helper text, secondary info.
- Border/hairline: `#E2E8DD`.
- Warning/awaiting-review amber: `#B26A00` on `#FFF4E5` — the `awaiting-review` payment state badge (D-04) and slip-under-review notice. This is a status color, not an action color; never use it for buttons.

**Accent (`#2E7D32`) is reserved for — explicit list, never "all interactive elements":**
1. Primary CTA button fill (the one primary action per screen: "ยืนยันและชำระเงิน", "สั่งซื้อ", "สั่งซ้ำ").
2. The active/selected state ring + check on a chosen delivery method or pack option.
3. The active step in the checkout wizard step-indicator (completed steps use accent, upcoming steps use border-neutral).
4. The **paid** / **in-stock** status badge and the ✓ on the payment-success screen.
5. Marketing/consent checkbox check-fill when ticked.

Everything else interactive (back links, secondary buttons, "แก้ไข" links, quantity steppers) uses neutral ink + border, **not** accent — this keeps the single primary action per screen unambiguous.

**Destructive (`#D32F2F`) is reserved for:** the cancel-order action, remove-item-from-cart action, the slip-verify **rejected** badge (duplicate / wrong-amount / wrong-payee — D-02/03/06), the **sold-out / removed-in-this-round** flag on reorder (D-20), and inline form validation errors.

## Copywriting Contract

All customer-facing copy is **Thai**. Tone: friendly, plain, farm-fresh — not corporate. Consistent with the locked Thai Rich Menu labels (D-18).

### Primary actions & wizard

| Element | Copy |
|---------|------|
| Wizard step 1 title (pick varieties/packs) | เลือกผักรอบนี้ |
| Wizard step 2 title (delivery) | วิธีรับสินค้า & ที่อยู่ |
| Wizard step 3 title (summary + slip) | สรุป & ชำระเงิน |
| Step-advance CTA (steps 1→2, 2→3) | ถัดไป |
| Back link | ย้อนกลับ |
| Primary CTA — place order & show QR | ยืนยันและชำระเงิน |
| Pay screen instruction | สแกน QR นี้ด้วยแอปธนาคารเพื่อโอน ฿{amount} แล้วอัปโหลดสลิป |
| Slip upload CTA | อัปโหลดสลิปการโอน |
| Reorder CTA (history) | สั่งซ้ำ |
| Free-shipping hint | ส่งฟรีเมื่อซื้อครบ ฿500 (เฉพาะส่งเอง/ขนส่งทั่วไป) |

### Empty states

| Screen | Heading | Body (+ next step) |
|--------|---------|--------------------|
| Order history — member, no orders | ยังไม่มีคำสั่งซื้อ | เริ่มสั่งผักสลัดสดรอบนี้ได้เลย แล้วประวัติจะแสดงที่นี่ · [ปุ่ม: สั่งผักรอบนี้] |
| Order history — guest (not logged in) | เข้าสู่ระบบเพื่อดูประวัติ | ประวัติและการสั่งซ้ำใช้ได้เมื่อเข้าสู่ระบบด้วย LINE · [ปุ่ม: เข้าสู่ระบบด้วย LINE] |
| Catalog — no open round | รอบขายปิดชั่วคราว | รอบถัดไปกำลังจะมา ติดตามได้ที่เมนู "ราคาวันนี้" หรือกดติดตามร้าน |
| Cart — empty | ยังไม่ได้เลือกผัก | เลือกผักสลัดที่อยากได้ แล้วมาต่อที่นี่ |

### Error states (problem + solution path)

| Situation | Copy |
|-----------|------|
| Slip verify — wrong amount (D-03) | ยอดในสลิปไม่ตรงกับคำสั่งซื้อ (ต้องโอน ฿{amount} พอดี) — โปรดโอนยอดที่ถูกต้องแล้วอัปโหลดสลิปใหม่ |
| Slip verify — wrong payee (D-02) | สลิปนี้ไม่ได้โอนเข้าบัญชีร้าน — โปรดสแกน QR ของร้านแล้วโอนใหม่ |
| Slip verify — duplicate (D-06) | สลิปนี้ถูกใช้ไปแล้ว — หนึ่งสลิปใช้ได้กับหนึ่งคำสั่งซื้อเท่านั้น โปรดแนบสลิปการโอนจริงของออเดอร์นี้ |
| Slip verify — API down / ambiguous (D-04) | เราได้รับสลิปแล้ว กำลังตรวจสอบโดยแอดมิน จะแจ้งผลทาง LINE เมื่อยืนยันการชำระเงิน |
| QR hold expired (D-09) | คำสั่งซื้อนี้หมดเวลาชำระเงินและถูกยกเลิกแล้ว ผักถูกคืนสู่รอบ — สั่งใหม่ได้ทันทีหากยังต้องการ |
| Delivery method blocked by freshness (D-13) | ผักในตะกร้าต้องส่งแบบ {allowedMethods} เพื่อความสด — โปรดเลือกวิธีจัดส่งที่รองรับ |
| Reorder — item now unavailable (D-20) | บางรายการไม่มีในรอบนี้หรือขายหมดแล้ว — โปรดตรวจสอบก่อนชำระเงิน |
| Generic network/server error | เกิดข้อผิดพลาด โปรดลองใหม่อีกครั้ง |

### PDPA consent copy (D-25/26 — captured at checkout, before name/address/phone)

| Element | Copy |
|---------|------|
| Usage-consent checkbox (required to proceed) | ฉันยินยอมให้ร้านเก็บและใช้ข้อมูลเพื่อดำเนินการคำสั่งซื้อและจัดส่ง ([นโยบายความเป็นส่วนตัว]) |
| Marketing-consent checkbox (separate, default **unchecked**) | ฉันยินยอมรับข่าวสาร โปรโมชัน และรอบผักใหม่ผ่าน LINE (ไม่บังคับ) |

### Destructive confirmations

| Action | Confirmation copy |
|--------|-------------------|
| Cancel order (customer) | ยกเลิกคำสั่งซื้อ: ยกเลิกออเดอร์นี้ใช่ไหม? ผักที่จองไว้จะถูกคืนสู่รอบ · [ยืนยันยกเลิก] / [ไม่ใช่] |
| Remove item from cart | ลบรายการ: นำ "{varietyName}" ออกจากตะกร้าใช่ไหม? · [ลบ] / [ยกเลิก] |
| Replace uploaded slip | เปลี่ยนสลิป: แนบสลิปใหม่แทนสลิปเดิมใช่ไหม? · [แนบใหม่] / [ยกเลิก] |

Destructive confirmations use a modal/bottom-sheet with the destructive-colored confirm button on the right; the cancel/dismiss option is always neutral and never pre-focused for a destructive default.

## Key Screen → State Inventory (for planner/executor & checker)

Each interactive screen must implement its full state set — the executor builds all listed states, the checker validates them.

| Screen | States to implement |
|--------|---------------------|
| Catalog / round browse (LIFF from Rich Menu "สั่งผักรอบนี้") | loading · has-items · no-open-round (empty) · item sold-out badge · error |
| Variety detail | loading · content (name/desc/photo + `storage_tips`/`washing_tips` care fields D-24; care fields hidden when null) · add-to-cart · error |
| Checkout wizard (3 steps, D-16) | per-step: valid · per-field inline error · step-blocked (freshness D-13) · consent-ungated (usage checkbox unticked → CTA disabled) |
| Delivery step (D-12/14/15) | method tiles (self / cold / general carrier / on-demand) · method disabled-by-freshness · selected · fee line (per zone×method flat) · free-shipping-applied state · round deliveryDate shown read-only |
| Pay screen — PromptPay QR (D-07/10/11) | QR shown (idempotent, does not re-arm timer) · hold-countdown visible · slip not-yet-uploaded · uploading · verifying · verified/paid · rejected (per reason) · awaiting-review (D-04) · hold-expired/cancelled (D-09) |
| Order history + reorder (member-only, D-19/20) | member list · guest gate (login prompt) · empty · reorder pre-fill with unavailable-item flags |
| PDPA consent (D-25/26) | usage checkbox (required) · marketing checkbox (optional, default off) · policy link |

**Notification copy (Flex cards, D-21/22 — rendered by LINE client, not DOM):** milestones = paid · packing/shipping · done · cancelled/hold-expired. Each Flex card carries an order-summary block + a deep-link button into the LIFF order page. Exact Flex JSON layout is Claude's-discretion (D-22); copy tone matches this contract. Cards target members with `line_user_id` only (D-23).
