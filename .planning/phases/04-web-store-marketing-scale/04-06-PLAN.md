<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin → broadcast send | Broadcasts reach real customers; must respect marketing consent (PDPA). |
| LINE → webhook | Inbound events must pass signature validation before any bot logic. |
| bot → payment | The bot must not handle money; it hands off to LIFF. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-18 | Repudiation/Privacy (PDPA) | broadcast to non-consented user | high | mitigate | Latest-marketing-consent filter + non-null line_user_id + opt-out (D-17, NFR-04); broadcast-audience.test.ts |
| T-04-19 | Spoofing | webhook signature bypass | high | mitigate | Untouched raw-bytes validateSignature block; bot logic strictly after it; regression test asserts bad-signature reject |
| T-04-20 | EoP | non-admin sending broadcasts | high | mitigate | requireRole owner|admin on all broadcast routes (V4) |
| T-04-21 | DoS | pg-boss worker on pooled endpoint | medium | mitigate | broadcast-send worker on DATABASE_URL_DIRECT via workerDb (Pitfall 6) |
| T-04-22 | DoS | LINE multicast recipient cap exceeded | medium | mitigate | Chunk audience ≤500 per multicast (Pitfall 7; reverify cap in LINE docs before shipping large segments — A1) |
</threat_model>
