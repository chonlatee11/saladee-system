# Phase 4 — UI Design Contract

> Visual and interaction contract for Phase 4 (Web Store, Marketing & Scale). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Inheritance rule (binding):** Phase 4 does NOT invent a new design language. The
> established Saladee token system already ships in `web/src/style.css` (02-UI-SPEC)
> and `web-admin/src/style.css` (03-UI-SPEC) — "one brand, N apps". The new Nuxt web
> store (D-01) and every new admin surface (promotions, loyalty, broadcast composer,
> carrier tracking, planting-recommendation card) **reuse the EXACT same `@theme`
> tokens**. This spec re-states that contract and adds only what Phase 4's new
> surfaces need (desktop store layout, product gallery, coupon/points fields,
> delivery-status enum, broadcast composer).

## Design System

| Property | Value |
|----------|-------|
| Tool | none (deliberate) |
| Preset | not applicable |
| Component library | none — plain Vue 3 SFC + Tailwind v4 CSS-first (`@tailwindcss/vite`), no Radix/Base-UI |
| Icon library | `lucide-vue-next` (already a dependency in both `web/` and `web-admin/`) |
| Font | `--font-sans: "Sarabun", system-ui, -apple-system, "Noto Sans Thai", sans-serif` — system stack, nothing self-hosted, no font request on first paint |

**shadcn gate — evaluated, N/A.** The stack is **Vue**, not React; shadcn is React-first,
and this codebase deliberately runs plain Tailwind v4 CSS-first with a shared `@theme`
token block across two shipped apps. D-01 locks the new store to **Nuxt (Vue) + Tailwind
reusing `web/` components**. Introducing shadcn (or shadcn-vue) mid-milestone would fork
the token system and break the very cross-app consistency the gate exists to protect.
Therefore `Tool: none`, registry safety not applicable. This is a settled upstream
decision, not an open question.

**Token source of truth (copy verbatim into the Nuxt store's `@theme`):** the block in
`web/src/style.css`. The Nuxt app imports Tailwind v4 the same way (`@import
"tailwindcss";` + `@theme { … }`) and reuses the `web/` Vue components (VarietyCard,
QtyStepper, EmptyState, SlipUploader, DeliveryMethodTiles, Spinner, BusyOverlay).

## Spacing Scale

Declared values (all multiples of 4) — inherited unchanged from `web/` + `web-admin/`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, badge padding |
| sm | 8px | Compact element spacing, chip gaps |
| md | 16px | Default element spacing, card padding, form field gaps |
| lg | 24px | Section padding, catalog grid gutter |
| xl | 32px | Layout gaps, desktop column gap |
| 2xl | 48px | Major section breaks, hero vertical padding, empty-state rhythm |
| 3xl | 64px | Page-level spacing, desktop hero block |

Layout constants (achieve via padding/width, keep the 4px grid):

| Token | Value | Usage |
|-------|-------|-------|
| sidebar | 240px | Admin expanded sidebar nav width (existing) |
| rail | 64px | Admin collapsed sidebar rail (existing) |
| store-max | 1200px | **NEW** — web-store desktop content max-width (centered), so the desktop layout (D-05) is a real multi-column grid, not a stretched mobile column |

Exceptions: touch targets on the storefront use a **48px** min interactive height
(`min-h-[48px]`, existing checkout CTA idiom) — a padding outcome on the 4px grid, not a
new spacing token.

## Typography

Two weights only (400 / 600), four sizes. Matches existing usage (`font-semibold` 600 +
`font-normal` 400 dominate; occasional `font-medium` 500 is being retired toward 600).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 600 | 1.4 |
| Body | 16px | 400 | 1.6 |
| Heading | 20px | 600 | 1.35 |
| Display | 28px | 600 | 1.25 |

Notes:
- **Body never below 14px** (readable Thai). 16px is the base (`html { font-size:16px }`).
- **Display (28px)** is used by the **NEW desktop store hero** (D-05) and store section
  titles; on mobile it may drop to Heading (20px). Still weight 600 — the 2-weight budget
  is not spent to add hero emphasis.
- Money / quantity columns render right-aligned with `.tabular`
  (`font-variant-numeric: tabular-nums`) — carries into coupon-discount, points-value, and
  order-total rows.

## Color

Inherited 60/30/10 "fresh-salad" palette — identical hex across all apps.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (`--color-canvas`) | Page/content background, cards, table body |
| Secondary (30%) | `#f1f5ec` (`--color-surface`) | Product cards, sidebar, sticky footer, table header, row hover, chips |
| Accent (10%) | `#2e7d32` (`--color-accent`) | see reserved list below |
| Destructive | `#d32f2f` (`--color-destructive`) | Destructive actions + negative status + errors only |

Supporting ink + neutrals (outside the 60/30/10 budget, unchanged): `--color-ink`
`#1b2a1b` (primary text), `--color-muted` `#5b6b5b` (labels/helper), `--color-hairline`
`#e2e8dd` (borders/dividers).

Status badge palette (badges / dots / inline status text ONLY — never buttons):
`positive #2e7d32` on `#f1f5ec`, `warning #b26a00` on `#fff4e5`, `negative #d32f2f` on
`#fdecea`, `neutral #5b6b5b` on `#f1f5ec`. **Reuse these for the NEW delivery-status enum
badges** (see Delivery Status section).

Chart categorical palette (reports, unchanged, stable channel↔color): `chart-1 #2e7d32`
(B2C), `chart-2 #1565c0` (B2B), `chart-3 #b26a00` (Subscription), `chart-4 #6a1b9a`,
`chart-5 #00838f`, `chart-6 #c2185b`, `chart-other #9aa69a`. **CROP-07 demand chart and any
web-store analytics reuse this mapping** — no new chart colors.

**Accent reserved for (explicit — never "all buttons/all interactive"):**
1. The **single primary CTA per screen** — storefront add-to-cart, checkout advance
   ("ถัดไป"), and the final pay CTA ("ยืนยันและชำระเงิน").
2. The **"ใช้คูปอง" (apply-coupon) confirm** and **"ใช้แต้ม" (redeem-points) confirm** —
   these are the primary action of their inline block; the coupon/points input itself is
   neutral.
3. The **active nav item** in the admin sidebar (existing rule).
4. **Positive status** dots/badges (via `--color-positive`, same hex).
5. The **selected-tile ring** (`ring-2 ring-accent` + fixed-footprint check badge) — the
   one approved "selected" pattern (03-14), reused for delivery-round pick, carrier pick,
   and any radio-tile group. No second selected-state variant.

Secondary/neutral actions (cancel, back, "แก้ไข", quantity steppers, coupon/points
inputs, broadcast "แสดงตัวอย่าง") use surface/hairline + ink — **not** accent.

## Copywriting Contract

Thai copy (project language). Reuses existing tone; empty/error states follow the
`EmptyState` component pattern (heading + optional body + optional slotted CTA).

### Phase-level primary CTA

| Element | Copy |
|---------|------|
| **Phase primary CTA** (web-store checkout) | `ยืนยันและชำระเงิน` (final pay); advance step = `ถัดไป`; product card = `ใส่ตะกร้า` |

### New-surface copy inventory

| Element | Copy |
|---------|------|
| Store hero primary CTA | `เลือกผักรอบนี้` |
| Add to cart | `ใส่ตะกร้า` |
| Cart empty — heading | `ตะกร้าว่างอยู่` |
| Cart empty — body + step | `ยังไม่ได้เลือกผัก — เลือกผักสลัดสดจากรอบนี้ได้เลย` (slot CTA: `เลือกผักรอบนี้`) |
| Store catalog empty (no open round) — heading | `ยังไม่เปิดรอบขาย` |
| Store catalog empty — body | `รอบถัดไปกำลังจะมา ฝากอีเมล/LINE ไว้เพื่อรับแจ้งเตือนได้` |
| Coupon field — label / placeholder | `โค้ดส่วนลด` / `กรอกโค้ดคูปอง` — action: `ใช้คูปอง` |
| Coupon applied — confirmation | `ใช้คูปอง {code} แล้ว — ลด {amount} บาท` (remove: `นำออก`) |
| Coupon invalid — error | `คูปองใช้ไม่ได้ — อาจหมดอายุ ถึงขีดจำกัดการใช้ หรือยอดยังไม่ถึงขั้นต่ำ ตรวจสอบเงื่อนไขแล้วลองใหม่` |
| Points block — label | `แต้มสะสม {balance} แต้ม (= {baht} บาท)` — action: `ใช้แต้มลดราคา` |
| Points earn hint (post-paid) | `คุณได้รับ {points} แต้มจากคำสั่งซื้อนี้` |
| Points redeem error | `ใช้แต้มไม่สำเร็จ — แต้มไม่พอ หรือเกินยอดที่ลดได้ ลองปรับจำนวนแต้ม` |
| Broadcast composer — send CTA | `ส่งบรอดแคสต์` / scheduled: `ตั้งเวลาส่ง` |
| Broadcast audience count | `ส่งถึง {n} คน (เฉพาะผู้ยินยอมรับข่าวสารการตลาด)` |
| Broadcast audience empty — heading | `ไม่มีผู้รับในกลุ่มนี้` |
| Broadcast audience empty — body | `กลุ่มนี้ยังไม่มีลูกค้าที่ยินยอมรับข่าวสารการตลาด (PDPA)` |
| Broadcast send error | `ส่งบรอดแคสต์ไม่สำเร็จ — ลองใหม่ หรือตรวจสอบโควตาข้อความ LINE` |
| Coupon composer empty — heading | `ยังไม่มีคูปอง` |
| Coupon composer empty — body + step | `สร้างคูปองส่วนลดแรกเพื่อกระตุ้นยอดขาย` (slot CTA: `สร้างคูปอง`) |
| Carrier tracking — save CTA | `บันทึกเลขพัสดุ` |
| Carrier tracking empty — heading | `ยังไม่มีเลขพัสดุ` |
| Carrier tracking empty — body | `เลือกผู้ให้บริการขนส่งและกรอกเลขพัสดุเพื่อเริ่มติดตาม` |
| CROP-07 recommendation card — heading | `คำแนะนำปริมาณปลูก (จากดีมานด์ย้อนหลัง)` |
| CROP-07 apply CTA | `ใช้ค่านี้เติมในแผนปลูก` |
| CROP-07 no-data — heading | `ข้อมูลดีมานด์ยังไม่พอ` |
| CROP-07 no-data — body | `ต้องมีประวัติการขายอย่างน้อย {N} รอบจึงจะแนะนำได้` |
| Sold-out / round cut-off at checkout | `หมดรอบนี้` (existing string, reused; blocks reservation) |
| Guest-checkout hint | `สั่งซื้อแบบไม่ต้องเข้าสู่ระบบได้ — เข้าสู่ระบบเพื่อสะสมแต้ม` |

### Destructive actions (each needs a confirm dialog)

| Action | Confirmation copy |
|--------|-------------------|
| Cancel a scheduled broadcast | `ยกเลิกการตั้งเวลาบรอดแคสต์นี้? ข้อความจะไม่ถูกส่ง` — confirm: `ยกเลิกการส่ง` |
| Deactivate / delete a coupon | `ปิดใช้งานคูปองนี้? ลูกค้าจะใช้โค้ดนี้ไม่ได้อีก` — confirm: `ปิดใช้งาน` |
| Remove a product image | `ลบรูปนี้ออกจากสินค้า?` — confirm: `ลบรูป` (cover image cannot be left empty — block if last) |
| Remove applied coupon/points at checkout | inline `นำออก`, no dialog (non-destructive, reversible) |

Destructive confirms use the destructive color for the confirm button only; the dialog
surface stays neutral. Confirm dialogs reuse a single shared modal pattern.

## Delivery Status Enum (D-22) — visual contract

Staff-updated status; each transition notifies the customer via LINE (Phase-2 seam).
Rendered as status badges using the existing status palette (never as buttons).

| Enum value | Thai label | Badge palette |
|------------|-----------|---------------|
| `pending` | `รอจัดส่ง` | neutral (`#5b6b5b` / `#f1f5ec`) |
| `handed_to_carrier` | `ส่งให้ขนส่งแล้ว` | warning (`#b26a00` / `#fff4e5`) |
| `in_transit` | `กำลังจัดส่ง` | warning (`#b26a00` / `#fff4e5`) |
| `delivered` | `จัดส่งสำเร็จ` | positive (`#2e7d32` / `#f1f5ec`) |
| `failed` | `จัดส่งไม่สำเร็จ` | negative (`#d32f2f` / `#fdecea`) |

Carrier pick (Grab / Lalamove / general) uses the selected-tile ring pattern
(`ring-2 ring-accent`). Labels/order are a Claude's-Discretion refinement (D-22) — planner
may adjust, but the palette mapping above is binding.
