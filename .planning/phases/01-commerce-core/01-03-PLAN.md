</objective>

| Boundary | Description |
|----------|-------------|
| staff client → catalog/round/price writes | must be owner/admin session |
| public client → catalog/price reads | open (D-03), no PII exposed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-11 | Elevation | unauthenticated/wrong-role catalog write | mitigate | requireRole("owner","admin") beforeHandle on every write route; deny-by-default; auth-boundary test asserts 401/403/2xx. |
| T-01-12 | Tampering | negative/fractional price or quota | mitigate | TypeBox `t.Integer({minimum:0})` on price/quota; money is integer satang (no float). |
| T-01-13 | Tampering | SQL injection via CRUD bodies | mitigate | Drizzle parameterized queries only. |
| T-01-14 | Info Disclosure | PII leak via public reads | mitigate | Public reads expose only catalog/price data — never customers/orders. |
| T-01-22 | Elevation | broken access control — staff-login scaffold trusts a CLIENT-SUPPLIED password hash → anyone forges an admin token, defeating every requireRole gate | mitigate | POST /auth/staff looks up the users row by email and verifies the submitted password against the STORED password_hash (Bun.password.verify); role is taken from the row, never the request; the passwordHash body field is removed. Forgery-regression test asserts a client-supplied hash cannot mint a token. |
| T-01-23 | Info Disclosure | user-enumeration via distinct unknown-email vs wrong-password responses | mitigate | Both paths return identical 401 { error:"invalid_credentials" }; no distinguishing signal. |
| T-01-SC | Tampering | supply chain | accept | No new packages this phase. |
</threat_model>
