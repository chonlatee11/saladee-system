## Phase Goal

**As a** customer, **I want to** place an order that instantly and safely claims my packs at a locked-in price, **so that** I never pay a changed price and never get a sold-out surprise after paying.

<objective>
Wrap the proven reservation core in the real `POST /orders` endpoint (D-02 — the same seam Phase 2 LIFF calls) and the staff-driven status pipeline, then prove no-oversell end-to-end at the HTTP boundary. This is the phase's headline user capability: a guest places a priced order that reserves stock atomically with a frozen snapshot, and staff move it through the pipeline.

Purpose: Criterion 2 + 4 — atomic reservation and the full status pipeline with an invoice-ready price-at-order-time snapshot.
Output: `routes/orders.ts` (open POST + staff PATCH), wired in `index.ts`, plus real-PG endpoint race, snapshot, cut-off, and cancel-release tests, and a Bruno order collection + parallel racer script.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| guest/member client → POST /orders | untrusted body (customer, tier, qty); open per D-03 |
| staff client → PATCH /orders/:id/status | must present a valid owner/admin session |
| concurrent POST /orders → round_stock | oversell integrity (PLAT-01) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Tampering | POST /orders oversell under concurrency | mitigate | Guarded reserve() inside db.transaction; end-to-end N-way race proves exactly one winner (Task 2). |
| T-01-06 | Tampering | price/stock tampering via client-supplied price or plants | mitigate | Body schema has NO price/plants field; server resolves price by tier from prices (OQ-2 override) and computes plants — snapshot is fully server-derived (D-16). |
| T-01-07 | Elevation | unauthenticated/wrong-role status change | mitigate | requireRole("owner","admin") beforeHandle on PATCH; POST stays open by design (D-03). |
| T-01-08 | Tampering | double-cancel double-release of stock | mitigate | Cancel release guarded by `status != 'cancelled'` + release() `WHERE reserved_plants >= n`; idempotency asserted. |
| T-01-09 | Tampering | negative / zero quantity | mitigate | TypeBox `qty: t.Integer({minimum:1})`; DB CHECK (qty > 0) from 01-01. |
| T-01-10 | Info Disclosure | customer PII via order reads | mitigate | Order read/PATCH is staff-guarded; only catalog/availability (01-04) is public. |
| T-01-SC | Tampering | supply chain | accept | No new packages this phase. |
</threat_model>
