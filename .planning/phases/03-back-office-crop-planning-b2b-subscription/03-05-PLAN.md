## Slice user story
**As a** แอดมิน, **I want to** ตรวจ draft จำนวนขายที่ระบบคำนวณจากปฏิทินเก็บเกี่ยวแล้วกด "เผยแพร่" ก่อนรอบเปิด (พร้อมแก้เองได้และคงค่าไว้ถาวร) และบันทึกผลเก็บเกี่ยวจริงพร้อม lot/best-before, **so that** จำนวนที่เปิดขายตรงกับผลผลิตจริง (แทนกรอกมือ) และมี traceability.

Vertical slice: web-admin (HarvestCalendar publish/override, HarvestLog) → API (harvest.ts: publish orchestration + override + log) → DB (round_stock.quota_plants + is_manual_override, harvest_logs). ครอบ Success Criterion 2 (CROP-04/05, INV-10) + admin publish gate (CROP-03 mapping D-07) + **round-open orchestration ที่การันตี reserve-before-B2C (CUST-05, Success Criterion 3)**.

Purpose: แทนที่การกรอกจำนวนขายมือของ Phase 1 ด้วย crop auto-feed (กด publish) + คง manual override ถาวร; publishQuota เป็น **single owner ของลำดับเปิดรอบ** — จอง standing (03-06) atomic ใน tx เดียวกับ quota แล้ว trigger subscription-generate (03-07) หลัง publish จึงไม่มี window ให้ B2C แย่งก่อน.
Output: publish/override/harvest-log + round-open orchestration end-to-end.
</objective>
